# Repository Guidelines

## Project Structure & Module Organization

This is a Bun workspace with frontend and backend packages. Root files include `package.json`, `bun.lock`, `index.ts`, and shared TypeScript config. The React frontend lives in `frontend/`; app code is under `frontend/src`, routes in `frontend/src/routes`, reusable UI in `frontend/src/components`, and static assets in `frontend/public`. The Elysia backend lives in `backend/`; source is in `backend/src`, routes in `backend/src/routes`, domain logic in `backend/src/domain`, schemas in `backend/src/db/schema`, scripts in `backend/scripts`, and Drizzle migrations/config in `backend/drizzle`.

## Build, Test, and Development Commands

- `bun install`: install workspace dependencies.
- `bun run dev`: run frontend and backend development servers together.
- `bun run --cwd frontend dev`: start Vite on port `8080`.
- `bun run --cwd backend dev`: run the Elysia API with file watching on port `3000`.
- `bun run --cwd frontend build`: build the frontend for production.
- `bun run --cwd frontend lint`: run the TanStack ESLint config.
- `bun run --cwd frontend typecheck`: run TypeScript checks.
- `bun run --cwd frontend test`: run Vitest once.
- `bun run --cwd backend db:master:migrate`: apply master Drizzle migrations.
- `bun run --cwd backend db:tenant:migrate`: apply tenant Drizzle migrations.

## Coding Style & Naming Conventions

Use TypeScript and ES modules throughout. Frontend formatting is defined by `frontend/.prettierrc`: 2 spaces, LF endings, no semicolons, double quotes, ES5 trailing commas, and 80-column print width. Prefer the `@/*` path alias inside each package. Use PascalCase for React components and service classes such as `SalesService.ts`; use camelCase for functions, variables, and route helpers. Keep generated files such as `frontend/src/routeTree.gen.ts` generated by tooling.

## Testing Guidelines

Frontend tests use Vitest with Testing Library. Place tests near the code they verify using `*.test.ts` or `*.test.tsx`, and run them with `bun run --cwd frontend test`. The backend currently has a placeholder `test` script, so add a real backend test command before relying on CI-style backend checks.

## Commit & Pull Request Guidelines

Recent commits use short, imperative messages, sometimes scoped, for example `create tenants separation` or `[sale]add files`. Keep commits focused and describe the behavior changed. Pull requests should include a summary, verification commands, related issue links when applicable, screenshots for UI changes, and notes for any migration or tenant-impacting change.

## Security & Configuration Tips

Do not commit local database files, secrets, or environment-specific configuration. Review Drizzle migrations before applying them, especially tenant migrations and `db:tenant:migrate:all`, because they can affect multiple tenant databases.
